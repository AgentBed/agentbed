# Response to review codex-001 (2026-08-23, at commit b4abb04)

Verdict accepted: **NEEDS REVISION**. ADR-001 is revised (Revision 2) rather than accepted as-was. Per-finding disposition below. "Accepted" = folded into Revision 2. "Phased" = accepted in direction, scheduled at a named gate, with the v0 posture stated honestly in the docs. "Rebutted" = we disagree and say why.

| # | Finding | Disposition |
|---|---|---|
| 1 | Root daemon too large a trust boundary | **Accepted (structure now, depth phased).** Revision 2 splits the design into an unprivileged gateway, a privileged broker with a fixed RPC surface, per-agent executors, and an independent rollback watchdog (ADR §5.0). Gateway+broker land at Gate 1; per-agent executor UIDs/netns at Gate 3. Retrofitting process boundaries is expensive, so the split is in the architecture from day one even though early implementations are thin. |
| 2 | "Every mutation is reversible" is false | **Accepted.** The blanket claim is withdrawn. New `docs/effects.md` defines four effect classes (declarative / data / external / forbidden); every tool call declares its class and rollback coverage; external effects require approval. G2 reworded. This was the review's most valuable finding. |
| 3 | No concurrency/crash-recovery contract | **Accepted.** v0 serializes all host mutations behind a single transaction lock; the transaction state machine with WAL, idempotency keys, base-revision checks, and recovery behaviour for every interrupted state is in `docs/effects.md` §3. "Rollback Tuesday's change after Wednesday's changes" is a *revert* (new forward transaction), never a state restore, and the docs now say so. |
| 4 | Phase 0 test doesn't prove automatic rollback | **Accepted.** An independent watchdog (separate process, armed before activation, `nixos-rebuild test` semantics + boot-default unchanged + hardware/systemd watchdog + out-of-band Proxmox observer) is now a Gate 1 deliverable, and the reviewer's six chaos cases are the Gate 1 acceptance matrix verbatim (`docs/roadmap.md`). |
| 5 | Identity and approvals underspecified | **Accepted in part, phased.** Adopted now: per-agent tokens with expiry/rotation/revocation stored via systemd-creds; approvals issued out-of-band and bound as single-use signed decisions to {tx digest, diff, agent identity, manifest digest, effect class, expiry, nonce}; stdio via a shim to a Unix socket with peer credentials. Phased: full MCP OAuth resource-server compliance is a hard gate for any exposure beyond a private tailnet, not for v0 whose only clients are the owner's own runtimes. The approval channel's independence limit is documented: if the same runtime controls the approval channel, approvals degrade to rate-limiting, not authorization — mitigations listed in threat model. |
| 6 | Scalar safety tier too coarse | **Accepted.** Safety is now a per-resource vector (root_config / packages / bootloader / kernel / plugin_data / home_data / external_effects / recovery_requires), reported by `system.info` and consumed by manifests. | 7 | Egress/credential injection is a hypothesis | **Accepted, and simplified per the reviewer's own suggestion.** General TLS interception and the Agentbed CA are **dropped from the design**. v0 uses connector-level credential injection: per-service connectors reached over per-identity Unix sockets, holding the credential, scoping it to exact origin/path/method, resolving destinations themselves (DNS rebinding moot), with redaction at the connector. Raw egress (no credentials) remains proxy-allowlisted; pasta/nftables behaviour is a Gate 3 probe with pass/fail evidence, not an assumption. |

## Answers to the blocking questions

1. **Threat model:** Agentbed v0 must contain *prompt-injected* agents — agents browse the web, so injection is table stakes and is the reason manifests exist. v0 does **not** defend against malicious signed plugins from a store (no store in v0) or a determined human attacker with host access. Full statement in `docs/threat-model.md`.
2. **"Reversible"** means host configuration (generation/snapshot) and plugin data (restore-tested snapshots). External-service actions are never reversible; they are effect class E (external) and gated on approval. G2 is reworded accordingly.
3. **Static per-agent tokens must work** in v0 (clients are the owner's own runtimes on a private tailnet). Standards-compliant OAuth is a hard precondition for any deployment reachable beyond that tailnet; tracked as a gate, not a v0 deliverable.
4. **Yes — shared-profile agents are mutually trusted by definition.** The design stays, narrowed and documented as a single trust boundary; isolated desktops are the default.
5. **Node-D is not disposable** (it runs the owner's production agent runtime). All experimental gates run on spare-node VMs under Proxmox with out-of-band console. Node-D adopts Agentbed only after the Ubuntu adapter passes the same chaos matrix on a throwaway Ubuntu VM. Node-D facts (`findmnt /`, `uname -r`, `podman --version`) to be recorded in `docs/evidence/node-d.md` before the Ubuntu gate is planned.
