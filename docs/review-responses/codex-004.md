# Response to review codex-004 (2026-08-23, Revision 4 working tree vs b4abb04)

Verdict received: **ACCEPTED WITH CONDITIONS stands; Gate 0 open but not closeable**. This working tree is **Revision 5**: all six findings accepted and folded in. Dispositions:

| Finding | Disposition in Revision 5 |
|---|---|
| COMMITTING can commit a partially activated generation (Critical) | **Accepted — and simplified per the reviewer's own proposal.** COMMITTING is now **boot promotion only** (`switch-to-configuration boot` of the already-running, already-probated closure; snapshot hosts promote/pin). Probation runs on the `test`-activated system; COMMITTING submits no systemd jobs and runs no activation scripts, removing the hung-job race by construction. The fencing path additionally verifies via systemd that no candidate-submitted jobs survive, and **mandatory invariants re-run immediately before `COMMITTED` on both the normal and post-fencing paths**. Chaos case added: a candidate systemd job outliving CLI termination (must be impossible on the boot-promotion path; verified). |
| OOB can wrongly revert a committed transaction (High) | **Accepted.** OOB arming is now a durable lease with a **terminal-state handshake**: before appending local `COMMITTED`, the watchdog must obtain an OOB acknowledgement (CAS on the OOB's mirrored transaction record); if the ack cannot be obtained before the OOB lease deadline, the OOB revokes the lease and fences (pauses/resets) the VM *before* any recovery acts. A lost final message can no longer leave OOB believing `COMMITTING` while the log says `COMMITTED`. Chaos case added: dropped final `COMMITTED`/disarm message. |
| Explicit `requires_approval` bypassed by class ceiling (High) | **Accepted — real authorization bug.** Policy precedence rewritten (effects.md §1): stage 3 is now the **explicit operation policy** (`deny` \| `requires_approval` \| `pre_authorized` scope) and `requires_approval` can never be bypassed by a low class; stage 4 (class ceiling) applies only to calls with no explicit policy; stage 5 (quota) is a **mandatory final veto** on every outcome. "First rule fires wins" wording removed. |
| Redirects no longer normatively governed (High) | **Accepted.** Restored as normative connector contract (ADR §5): automatic redirects disabled; where a named operation permits them, each hop is parsed and authorized as a fresh destination, credentials stripped before re-evaluation and reinjected only for the newly authorized exact origin, resolution re-pinned per hop, hop count limited (default 3). Plain proxy: canonical CONNECT authority must match visible SNI; absent/encrypted SNI (ECH) and alternate tunnel protocols rejected. |
| Footprint declarations claimed but absent (High) | **Accepted.** Sample manifest now carries required `affected_resources` / `added_effects` on both service-control entries and package allowlist entries, with the rule that **adapter-resolved metadata (scriptlet/unit inspection) overrides self-declaration** and unresolved footprints are refused. |
| Canonical digest has no canonical representation (Medium) | **Accepted.** The canonical form is **RFC 8785 (JCS)** serialization of the fully validated, schema-projected typed operation, computed inside the broker; duplicate keys and non-interoperable numeric forms rejected at validation; approval UI, ledger, connectors and replay checks use those exact bytes, never a re-serialization. |
| Terminology drift (Medium) | **Accepted.** E examples now egress-based everywhere (effects.md, goals.md, ADR §2); `desktop_data` added to the §5.3 vector text with D-and-M refusal wording; goals.md status updated; residual `rev. 3` subsection labels removed; "later phase" → "behind a later gate". |
