# Roadmap — gated, not week-numbered

**Status:** Revision 6 · 2026-08-23 · verdict codex-003/004/005: ACCEPTED WITH CONDITIONS — **Gate 0 closed** ([evidence](evidence/gate-0.md)), Gate 1 open; conditions below are exit criteria. Replaces the phase/week table from ADR-001 Revision 1. A gate closes only with evidence recorded in `docs/evidence/`; calendar estimates are secondary. The prior 8-week horizon is retargeted to: **NixOS-only alpha through Gate 3, no desktops/plugins/Ubuntu/production.**

## Gate 0 — Ground truth
Threat model (`threat-model.md`), effect taxonomy and transaction contract (`effects.md`) reviewed; adjacent-technology sweep (polkit/Cockpit, OPA/Cedar, SPIFFE/SPIRE, secretless brokers, gVisor/Kata/Firecracker, transactional-update/bootc/rpm-ostree) recorded in `research/`; split-process spike: unprivileged gateway ⇄ privileged broker over a Unix socket with peer creds, fixed RPC, one end-to-end read tool (`system.info`).
**Exit conditions (codex-003/004):** terminology reconciled across all non-historical docs; approval and ledger schemas bind the exact effect set + **RFC 8785 JCS canonical operation digest** (construction frozen in [protocol.md](protocol.md) §4, together with the v1 envelope the spike's fixed RPC implements); policy precedence with explicit operation policy at stage 3 (out-of-bounds pre-authorization requires approval or declared deny — never the class ceiling) and quota as mandatory final veto (effects.md §1) is normative; `service.control` uses the `service_state` resource with the desired-state rollback contract; service/package manifest entries carry enforceable `affected_resources`/`added_effects` fields with adapter resolution overriding self-declaration; the RPC spike demonstrates that the **broker, not the gateway, is the authorization authority** (a forged gateway request without valid identity is refused by the broker).
**Exit evidence:** docs merged after external review; spike builds and passes an RPC fuzz smoke test + the forged-request test.

## Gate 1 — One safe transaction
Serialized transaction engine with WAL + recovery per `effects.md` §3; Nix adapter (`config.propose`, `tx.*`) using `nixos-rebuild test`; independent watchdog + Proxmox out-of-band observer. Staff-readiness design conditions 2 and 3 (below) start applying here.
**Exit conditions (codex-003/004):** only the watchdog durably chooses `BEGIN_COMMIT` vs `BEGIN_REVERT` (single-writer decision log); COMMITTING is compound boot promotion (system-profile advancement + `switch-to-configuration boot` + agreement verification, crash-recoverable across the profile/bootloader boundary) with no second live activation; the prepared OOB handshake (`COMMIT_PREPARED` → local `COMMITTED` → receipt) resolves both lost-message crash gaps via the local decision log; an expired lease fences and terminates the commit worker — and verifies no candidate systemd jobs survive — before any revert; mandatory invariants re-run immediately before `COMMITTED` on both normal and post-fencing paths; the OOB terminal-state acknowledgement precedes local `COMMITTED` (dropped-final-message test); epoch high-water mark survives WAL truncation and system rollback, stale OOB actions rejected; OOB detects watchdog failure independently of gateway health (signed heartbeat) and explicitly selects the base generation; boot filesystems and WAL storage flushed before disarm.
**Exit evidence:** the full chaos matrix of effects.md §4 (including watchdog death during COMMITTING, lease overrun, WAL/decision-log corruption, epoch-store rollback, stale OOB replay, OOB reset after boot-target change) passes on a spare-node VM, each case with decision-log/WAL output and console capture — the anchored audit ledger itself lands at Gate 2; deliberate network-breaking change reverts with no human action.

## Gate 2 — Identity, approvals, audit
Per-agent tokens (issue/expire/rotate/revoke, systemd-creds storage); single-use signed approvals bound to {tx digest, diff, agent id, manifest digest, exact effect set, canonical operation/body digest, expiry, nonce}, delivered on a channel independent of the requesting runtime; ledger hash chain anchored to a **WORM destination** (compliance-mode retention, write-only host credential, anchoring key outside the broker — ADR §5.2) with defined offline behaviour (`COMMITTED_UNANCHORED` refuses further D/M); E outcome machine (effects.md §3b) with durable approval consumption; stdio shim → Unix socket. Staff-readiness design conditions 1 and 4 (below) bind here.
**Exit evidence:** replayed approval rejected; revoked token rejected; ledger tamper after anchor detected; anchor-credential cannot delete or rewrite (probed); crash between approval consumption and dispatch yields `DISPATCHING`/`OUTCOME_UNKNOWN`, never a reusable approval or an automatic retry; a provider-without-idempotency-key path and an `OUTCOME_UNKNOWN` reconciliation path are both exercised.

## Gate 3 — Enforcement
Manifest compiler v1: fs/net/system scopes → broker policy + Landlocked helper for `shell.exec`/`file.*` (probed ABI, deny-degrade) + cgroup-keyed nftables default-deny + one connector with scoped credential injection (origin/path/method) over a per-identity Unix socket; pasta/nftables lifecycle probe with pass/fail writeup.
**Exit conditions (codex-003/004):** ASCII A-label origin policy; binary IP classification incl. IPv6 edge cases (mapped/compressed/zone-id); no ambiguous HTTP framing accepted (typed RPC only); CONNECT-UDP/MASQUE/Upgrade disabled; automatic redirects disabled with per-hop reauthorization where explicitly permitted (credentials stripped, reinjected only for the newly authorized origin, hop limit); plain-proxy CONNECT authority bound to visible SNI, ECH and alternate tunnels rejected; callback/webhook/import-URL fields validated as external destinations; credential-reflecting responses cannot reach the caller; wire and decompressed size limits.
**Exit evidence:** red-team script driving a "prompt-injected" agent (threat-model T2) cannot read outside fs scope, reach a non-allowlisted host, or extract a credential; cross-identity connector access fails (`SO_PEERCRED` mismatch, session-bound reference replay from another identity, FD passing); encoded-path traversal, caller-supplied authority/framing fields, credential-forwarding redirects, callback-URL exfiltration, and credential reflection are all rejected; attempts are attributed in the ledger. Gate 3 also requires stable per-identity UIDs and `0700` runtime dirs wherever executors reach connectors directly.

**— NixOS-only alpha ships here. —**

## Gate 4 — Plugins
Quadlet plugin runtime with **one service user per plugin trust domain** (own subuid range, storage, runtime dir); one trivial plugin (time tracker) with data snapshots, migration, export, restore test, MCP surface.
**Exit evidence:** plugin survives host rollback with data intact; restore test executed, not just documented; a deliberately "compromised" test plugin cannot control or read a sibling plugin's containers, storage or volumes.

## Gate 5 — Ubuntu adapter
apt + Btrfs snapshot adapter implementing the per-resource safety vector; chaos matrix re-run on a throwaway Ubuntu VM. Precondition: `docs/evidence/node-d.md` (findmnt /, uname -r, podman --version, OOB recovery).
**Exit evidence:** same chaos matrix as Gate 1 (effects.md §4), honest safety vector reported (including any `none` rows).

## Gate 6 — Desktops
Per-agent desktop containers (computer-use-linux + KasmVNC), snapshot/restore, takeover; opt-in shared desktop documented as a single trust domain; desktop input carries E whenever the desktop has external egress; desktop profiles live on the `desktop_data` resource.

## Staff-readiness conditions (from [research/agent-runtime-vision.md](research/agent-runtime-vision.md) §6)

AgentBed Staff (the deferred first-party runtime) imposes four conditions on the MCP surface. They are **design constraints on how features are built when they land, not new exit tests** — cheap now, expensive to retrofit:

1. **Gate 2 — token store representability.** The token/identity store schema must be able to represent parent→child credential chains (token → parent chain → manifest), so a later "derived attenuated credentials" feature (a parent identity requests a short-lived child credential bound to a broker-subset-checked narrowed manifest) is additive. Issuance itself is a Later item; the same mechanism is what would make skill-level narrowing (ADR §6.3) a host boundary.
2. **First release of `agentbed://events` (Gates 1–3 window).** The events resource ships **durable and cursor-resumable** (replay from a client-held cursor) from its first release — never fire-and-forget-only. Webhooks remain a convenience on top. An event-driven supervisor that crashes and rehydrates depends on replay.
3. **Gate 1 onward — cheap R-class status surface.** `tx.status`, ledger queries and per-agent activity summaries stay fast and cheap enough to be called conversationally (sub-second, no heavyweight auth round-trips beyond the session token). Verified informally per gate, not a chaos-matrix item.
4. **Gate 2 — approval-pending notifications subscribable.** The *fact* that an approval is pending (id, effect class, expiry — never the grant capability) is exposed as a subscribable event, so an external runtime can tell its owner an approval is waiting on the independent channel without being able to approve it.
